# moNa2 v2 + COROPIT キーマップ検討

用途回答前の仮案。QWERTYを維持し、配列案はまだファームウェアへ適用しない。

## 第一候補：文章・ブラウザ・AI操作

- ベース：通常の文字と頻用修飾キー。重複Commandの片方をControlにする候補。
- 親指：Space、Enter、Backspaceを押しやすい位置に確保。英数 LANG2／かな LANG1 は単独で使える位置を優先。
- 数字・記号：右側テンキー、左側に括弧・引用符・イコール。メール、表計算、Markdownの頻度で配置を決める。
- ナビ・編集：矢印、行頭末尾、単語移動、選択、コピー・貼り付け・取り消し。
- マウス：右手でボールを動かして左手で左クリック・右クリック・ドラッグできる案を試す。右手クリックの現行案とも比較する。
- 設定：接続先、USB/BLE切替、Studio、bootloader。ペアリング消去は押し間違えにくい位置へ。
- AI操作：音声入力、スクリーンショット、アプリ切替は候補。アプリやOS側の割当が必要なキーは、単独で機能するものとして扱わない。

## 比較候補

1. 現行踏襲：12層のまま慣れる。変更が少ない一方、OS別の重複と移動経路を覚える必要がある。
2. Mac日常用：上記の役割に整理。第一候補。ファームウェア内部のレイヤー番号と自動マウス層の参照は実装時に合わせる。
3. コード入力用：日常用に記号対、Esc、Control、ターミナル操作を優先する調整。ホームロウ修飾は打鍵の癖を見て後から試す。

## 到着後に決めること

親指の届き方、短押し／長押しの誤判定、ボール操作中のクリック手、Macのキーボード入力ソース（ANSI/JIS）、必要なアプリ用ショートカット。

最初に全レイヤーを作り直さず、USBでハードウェア確認 → Macベースと日本語切替 → 数字・ナビ → マウスの順に変更する。

## 現在の配列を読んで確認した点

- `config/mona2.keymap` の MAC（レイヤー1）は、最下段の `LEFT_GUI` と `LEFT_WIN` が同じCommandに相当する。Controlを常用するなら片方を置き換える候補。
- MACベースには `LANG1`／`LANG2` の直接割当がない。日本語切替を多用するなら優先して確保したい。
- MACでは `Space` 長押しで MOUSE_M（5）、バッククォート長押しで NUM_M（3）、マイナス長押しで SCRL_M（7）へ移る。文字入力とレイヤー操作の兼用が好みに合うか試す。
- BLE_M（11）はスラッシュ長押しから入り、bootloaderや `BT_CLR_ALL` も置かれている。通常操作と保守操作を近づけすぎない候補にする。
- 現状はOS別に12レイヤーある。案の「数字」「編集」「設定」は役割名であり、レイヤー番号をそのまま減らしてよいという意味ではない。自動マウス層などの参照先も実装時に検証する。

## 配列保存の扱い

Studioで保存したキーマップは、後から `.keymap` を書き換えて再ビルドしても、そのままでは置き換わらない場合がある。到着後の試行はStudioで進め、採用した配列をソースへ戻す段階で復元操作とバックアップ方法を決める。現時点では配列案を適用していない。

参考：[ZMK Studio の Keymap Changes](https://zmk.dev/docs/features/studio#keymap-changes)。DYA Studio固有のマクロ・コンボ編集については、使用中の版で実機確認する。

## 採用前に検討する項目

1. MacからWindows用操作層に入る経路：MACのセミコロン長押しは `&lt 4 SEMICOLON`、親指コンボは `&lt 4 ESC` で、どちらもMOUSE_W（4）へ入る。Macの取り消し／貼り付けを期待するならMOUSE_M（5）への経路に整理する。全OS共通コンボを一律5へ変えるとWindows側に影響するため、OSごとの利用方針を決めてから実装する。
2. 設定層への入口を通常の記号キーから分離する。接続先切替と接続情報消去は同じ頻度の操作ではない。
3. 実ファイルには静的 `zmk,combos` があり、READMEのruntime combo/macro移行済みという説明と一致しない。今回は変えていない。Studioで使える機能は接続後に確認し、必要なら実装を検証する。

いずれも今回のキーマップ検討の候補であり、配列へはまだ適用していない。
